### Challenges and Friction

1. Requirement drift in Story 4.2 caused a reverted iteration before final alignment.
2. Initial implementation pressure favored fast visible labeling in output text rather than the intended status-bar channel.
3. Sprint tracking still allows epic-level status drift when stories are done but epic state remains in-progress.

### Key Lessons Learned

1. UI-context labels and payload content must stay separated by design, not only by review feedback.
2. Story acceptance criteria need explicit "where behavior lives" language for rendering concerns.
3. Metadata contracts should be centralized as constants to avoid producer or consumer drift.
4. Regression tests should lock output ordering and payload purity whenever output formats evolve.
5. Retro action-item tracking in sprint status is necessary to verify follow-through across epics.
