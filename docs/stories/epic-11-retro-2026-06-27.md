## What Went Well

### 1. 100% story completion with clean sequential handoffs

All six stories shipped in dependency order without mid-epic corrections. The scope boundary sections in each story spec were effective — by the time Story 11.4 was implemented, the boundary between 11.4 (stop) and 11.3 (restart) territory was unambiguous. No scope creep, no re-do.

### 2. Review process caught real defects every story

Code review was not ceremony. Notable catches:

- **11.1**: Non-string `host` reused the "host cannot be empty" error message (factually wrong type error) — patched same day.
- **11.2**: TOCTOU race on the single-active-connection guard — two concurrent launches could both observe `getActiveConnection() === undefined` before either set the singleton. Fixed with an in-flight guard using the `connecting` state transition (set synchronously before the first `await`).
- **11.6 × 2**: `execution-messages.ts` still referenced the dead `Reconnect` command; three orphaned `bundle.l10n.json` keys not cleaned up — both patched.

### 3. Architectural discipline held throughout

The single active connection constraint, transport ownership, and DevTools coexistence remained first-class across all six stories. No second connection registry appeared. The TOCTOU fix was architecturally clean (state-transition guard, not a mutex). Epic 10's transport boundaries were stable enough to build on without renegotiation.

### 4. Subscription-timing checklist item from Epic 10 was applied

The Epic 10 retro committed to a standing code-review check for event subscriptions registered after replay/enable mutations. Story 11.2's TOCTOU fix shows this class of thinking being applied proactively — the race was caught in review, not discovered in production.

### 5. Smooth overall delivery

Project Lead assessment: everything went smoothly. No mid-epic course corrections, no blocking surprises, no external dependency failures.

## Challenges and Growth Areas

### 1. Story 11.4 manual smoke checkboxes unchecked in story record

The smoke steps in Story 11.4 were run but the checkboxes were not ticked before the story was marked `done`. The quality gate was met; the documentation habit was not. This is a low-severity process miss but it erodes the value of the story record as a verification artifact.

**Root cause**: No gate prevents a story from reaching `done` with unchecked task items.

### 2. l10n hygiene required two post-review patches in Story 11.6

`execution-messages.ts` still referenced the dead `Reconnect` command, and three orphaned `bundle.l10n.json` keys went undetected until review. The Epic 10 retro committed to an l10n sweep before the next localized feature — that sweep did not happen proactively before 11.6.

**Nuance**: the dead strings could not be fully removed until 11.6 (the commands didn't exist until 11.6 retired them), so the sweep was structurally blocked. But the sweep should have been part of 11.6's own scope rather than a review discovery.

**Root cause**: No automated check exists to detect orphaned `bundle.l10n.json` keys. Review is the only safety net.

## Development Patterns Not to Repeat

1. Do not mark a story `done` before all task checkboxes are checked. For unchecked manual smoke steps specifically: ask the Project Lead directly before proceeding with code review.
2. Do not rely on review alone to catch orphaned l10n keys — add an automated cross-reference check so the gap is caught before review.
3. Do not leave subscription-timing as tacit knowledge — the code-review checklist item should be written down and findable, not just remembered.

## Key Insights

1. **Scope boundary sections are worth the investment.** Every story in Epic 11 had a "Scope Boundary (Read First)" section. The sequential delivery without creep validates this pattern — codify it for future epics.
2. **Review-driven defect detection works when reviews are adversarial.** Four patches from real review sessions is a healthy signal. The TOCTOU catch is the standout — invisible class of bug in an event-replay path, caught before it shipped.
3. **The manual-test kit is a pre-Epic-3 gate, not an overdue item.** Epic 11 was subtractive (command retirement, lifecycle rewiring) — prepared cells and a step-by-step plan add minimal value for that kind of work. Epics 3 and 4 introduce user-facing output behavior where you need to _see_ the result. Build the kit before Epic 3 implementation begins.
4. **Process improvements need to survive context switches.** The l10n sweep and integration hang documentation from Epic 10 both went unaddressed because they were tacit action items with no enforcement surface. Automation or a checklist beats memory.
