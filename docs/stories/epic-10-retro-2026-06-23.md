Date: 2026-06-23

## Summary

Epic 10 delivered a first-class VS Code notebook-cell debugging workflow through a dedicated, extension-owned Debug Adapter Protocol (DAP) adapter, while preserving CDP session multiplexing and browser DevTools coexistence. Across Stories 10.1–10.5 the team shipped DAP session bootstrap and lifecycle, verified breakpoint binding, stack/scope/variable inspection with lazy expansion and watch evaluation, full stepping controls with deterministic pause synchronization, and integration-level validation of dual-client (VS Code + DevTools) coexistence.

The strongest outcome was architectural discipline: a thin inline DAP adapter routing to a `DebugSessionManager` over a single `BrowserDebuggerSession` transport, with `sessionId` on every CDP command so coexistence is implicit rather than special-cased. The team also honored the Epic 2 retro's "research-first" gate — Story 10.3 validated empirical hypotheses (H1–H5) against a live Foundry target before committing inspection design.

## What Went Well

### 1. Research-first gate honored and a failed hypothesis retired

Story 10.3 validated five empirical CDP hypotheses (callFrame caching, `globalThis` resolution, `evaluateOnCallFrame` side-effect rejection, value-size capping) against a live Foundry target before locking inspection design — exactly the gate the Epic 2 retro demanded before any Epic 10 work. Story 10.1 retired Story 2.5's always-on CDP mirror and moved `Debugger.enable/disable` into session lifecycle, closing a flagged Epic 2 debt item.

### 2. Transport discipline kept coexistence implicit

Every new CDP operation (breakpoints, properties, evaluate, step) was added to the `BrowserDebuggerSession` interface rather than scattered into adapters. Because every command carries `sessionId`, flat-session DevTools coexistence "just works," and Story 10.5 proved it at integration level rather than by assertion alone.

### 3. Simplicity favored over ceremony

Story 10.4 deliberately declined to build a pause-event serializer. A single-threaded notebook runtime, a single synchronous `onPaused` subscriber, monotonic `pauseVersion`, and VS Code's sequential step queueing already guarantee deterministic ordering. The complexity was added only where a real defect demanded it.

### 4. Code reality moved ahead of the risk register

The CDP integration suite is now wired into `release.yml` (a "Run CDP integration tests" step with real Chrome), closing the blocker the Story 10.5 record had flagged. The most recent integration run was green.

## Challenges And Growth Areas

### 1. Manual testing lacked a reusable kit (primary friction)

The Project Lead's biggest pain was not implementation — it was verification. There was no clear, step-by-step manual test plan to execute after implementation, and no prepared, ready-to-run notebook cells. `tests/files/manual-test.html` (a `/game` page with copy-paste `add` / `runDemo` / `inspect` snippets) was the single biggest helper, but it was authored late and exists only once. The Epic 2 retro made "manual smoke is a release gate" a rule without supplying the tooling to execute that gate efficiently.

### 2. Subscription-timing bug class appeared twice

`breakpointResolved` (10.2) and `scriptParsed` (10.4) were both registered _after_ a replay/`enable()` mutation, silently dropping events fired during the mutation. Both were fixed by subscribing before the mutation. This is an invisible, recurring failure mode that warrants a standing code-review check.

### 3. Localization completeness gaps recurred

Stories 10.2 and 10.3 surfaced mixed English/localized templates, missing `l10n/bundle.l10n.json` keys (e.g. `<anonymous>`), and debug-only strings polluting translation work.

### 4. CI integration hang was known but undocumented as a risk

The integration suite was deliberately kept out of CI because it hung. The hang was not a flaky test — it was a real defect: the app server blocked on `Close()` waiting for active connection termination. This was a conscious, correct decision, but it lived as tacit knowledge rather than a tracked risk until root-caused.

## Development Patterns Not To Repeat

1. Do not ship a "manual smoke is required" rule without also shipping a reusable manual-test kit (prepared page + ready-to-run cells + step-by-step plan).
2. Do not register event subscriptions after the state mutation / replay loop they need to observe; subscribe first and document the ordering.
3. Do not allow mixed English/localized templates or undeclared `l10n` keys to reach review.
4. Do not let a known infrastructure risk (CI hang) remain tacit; capture it as a tracked item with a root-cause owner.
5. Do not let the `epic-N` tracking key drift from completed story state at closeout.

## Key Insights

1. Process rules need matching tooling. "Manual smoke is a release gate" only works if the developer has a prepared kit to run it; otherwise the gate becomes the bottleneck.
2. Subscription timing is a distinct, recurring bug class in event-replay systems — worth an explicit review checklist item, not ad hoc discovery.
3. Coexistence is architectural: routing every CDP command through one transport with a `sessionId` parameter makes DevTools coexistence implicit and testable.
4. A hang is a defect, not noise. The CI hang root cause (app server `Close()` waiting on active connections; fixed by stopping Chromium before the app server so sockets drain first) turned an excluded suite into a release-gating one.
5. Out-of-sequence epic selection is legitimate when value is reassessed; Epic 10 ahead of 3–9 was an intentional value call after the Epic 1–9 redaction.
